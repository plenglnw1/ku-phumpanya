# 1.5.2 Load test: 30 concurrent users

**Status: BLOCKED.** The script is ready, but the gate run has not been done. It needs the three decisions under "Before the gate run".

## Criteria

- 30 concurrent users.
- p95 response time ≤ 5 s.
- Error rate ≤ 1 %.

## Script

`loadtest/k6-gate-1.5.2.js` uses k6 with these settings:

- **Load profile:** ramp to 30 virtual users over `RAMP` (default 30 s), hold for `HOLD` (default 3 min), then ramp down.
- **Thresholds:** `p(95) < 5000 ms`, `max < 10000 ms`, `http_req_failed < 1 %`, `checks > 99 %`. k6 exits non-zero when a threshold fails.
- **Each iteration:**
  1. Public pages `/`, `/learn/`, `/smart-picks/`, `/up`.
  2. With `SESSION_COOKIE` and `XSRF_TOKEN`: `/api/user`, recents, suggestions, Smart Picks, progress, and a stored result from `HISTORY_IDS`.
  3. With `RUN_SEARCH=1`: a new `POST /api/search` with one of 6 BCG queries.
  4. A think time of 1–3 s.

To run it:

```bash
BASE_URL=https://phumpanya.ku.ac.th \
SESSION_COOKIE='phumpanya-session=...; XSRF-TOKEN=...' XSRF_TOKEN='...' \
HISTORY_IDS=12,13,14 \
k6 run --summary-export=loadtest/result-1.5.2.json loadtest/k6-gate-1.5.2.js
```

Take the session from a test KU Google account in the browser. Do not commit cookies.

## Before the gate run

1. **Gemini quota.** On the free tier each model allows 20 requests a day. Thirty users searching would exhaust it within the first minute. After that, synthesis falls back to the retrieval-only draft. The run would still pass, but it would not measure synthesis.
   - Either run with `RUN_SEARCH=1` on a paid key,
   - or measure synthesis separately and run the load test without `RUN_SEARCH`.
2. **RAM on the KU VM.** The VM has 3.9 GB, no swap, and no sudo, and it runs Apache/PHP, MySQL, Elasticsearch, and Neo4j together.
   - On 2026-10-29 a single heavy job (`links:check`, hundreds of outbound requests) pushed load to 81. The kernel OOM-killed Elasticsearch and Neo4j.
   - The `*/10` cron watchdogs restarted both within about 10 minutes.
   - A 30-user run carries the same risk. Ask สำนักบริการคอมพิวเตอร์ for swap or more RAM, or accept the risk and run off-hours with someone watching `es-ctl.sh status` and `kg-ctl.sh status`.
3. **Load generator and timing.** Run from a machine on the KU network or VPN, not from the KU host itself. Agree on a time window with สำนักบริการคอมพิวเตอร์.

## Latency already measured (single user, KU host)

| Step | Time |
|------|------|
| Retrieval-only draft (`AgentPipeline::draft`, Elasticsearch docs + relations) | p50 ≈ 17 ms server time |
