# 1.3.6 Automated tests and coverage

CI (`.github/workflows/deploy-ku.yml`, job **Test**) runs on every pull request and every push to `main`:

```bash
php artisan test --coverage --min=55 --coverage-clover=clover.xml
```

- **Coverage driver:** pcov.
- **Artifacts:** `coverage.txt` (per-file table) and `clover.xml`, uploaded as the `coverage` artifact of each run.
- **Gating:** the run fails below 55 % line coverage.

## Result (PR #7, 2026-10-29)

- **Tests:** 160, of which 8 are skipped. The skipped tests need a live Neo4j or MySQL.
- **Total line coverage:** 59.5 %.

| Area | Coverage |
|------|----------|
| API controllers (search, progress, profile, consent, smart picks, learning, reference, admin) | 83–100 % |
| GraphRAG agent pipeline (pipeline, formatter, basic/intermediate tiers, service) | 100 % |
| Synthesizer / sub-agent / advanced tier | 77–98 % |
| Retrieval (RetrievalLinker / HybridRetriever) | 92 % / 54 % |
| Smart Picks recommender | 82 % |
| Neo4j client / Cypher guard | 95 % / 86 % |

The uncovered remainder is mostly one-off corpus maintenance commands that run against the live index:

- `corpus:backfill-*`
- `corpus:refresh-cached-links`
- `EnrichForestProjects`
- `ElasticIndexer`
- `GraphSeedBuilder`
- `QdrantRetriever`, which is disabled on KU

## Route coverage

Every route in `routes/api.php` has a feature test. The last gaps were `GET /api/admin/search-logs/export` (now in `SearchLogExportTest`) and the new routes `/api/progress` and `/api/consent`.

## End-to-end (gate 1.5.1, API level)

`tests/Feature/E2E/SearchToLearningPathTest.php` runs the full journey for each combination of 6 BCG topics and 4 pilot faculties, 24 cases in all:

1. Search.
2. Stored result.
3. Recents.
4. Complete a module.
5. Progress summary.

All 24 cases pass. The browser-level journey belongs to KU-BCG Playwright (frontend handoff).
