# 1.5.3 PDPA and security controls

Evidence collected on 2026-10-29 against production at `https://phumpanya.ku.ac.th`. Config values were read with `php artisan tinker` on the KU host; secrets were not read.

## Transport

| Control | Evidence | Status |
|---------|----------|--------|
| HTTP redirects to HTTPS | `curl -I http://phumpanya.ku.ac.th/` returns `301` to `https://phumpanya.ku.ac.th/`, via `deploy/ku-vm/html-root.htaccess` | Pass |
| HSTS | `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload` | Pass |
| Other headers | `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: same-origin` | Pass |

## Session

| Control | Evidence | Status |
|---------|----------|--------|
| Idle timeout of 30 minutes | `session.lifetime = 30`. The XSRF cookie has `Max-Age=1800` | Pass |
| Session ends when the browser closes | `session.expire_on_close = true`. The session cookie has no `Expires` | Pass |
| No remember-me | Google login calls `Auth::login($user)` without remember | Pass |
| Cookie flags | Session cookie: `secure; httponly; samesite=lax`. XSRF cookie: `secure; samesite=lax` | Pass |
| Session payload encrypted at rest | `session.driver = database`, `session.encrypt = true` | Pass |
| Idle warning in the UI | Countdown before the 30-minute expiry, then redirect to login | Frontend (KU-BCG, Tigger) |

## Authentication

| Control | Evidence | Status |
|---------|----------|--------|
| Password login disabled; KU Google only (`@ku.th`) | `auth_flow.password_login_enabled = false`. `POST /api/auth/login` returns `403 {"message":"Password login is disabled."}` | Pass |
| No demo accounts | `app:purge-demo-users` ran on deploy. Prod has 0 users matching `%@phumpanya.test` | Pass |
| No credentials in git history | `1.5.4-credential-scan.md` (gitleaks, both repos) | Pass |

## Personal data

| Control | Evidence | Status |
|---------|----------|--------|
| Minimal profile data exposed | `#[Hidden]` on `App\Models\User` covers `password`, `remember_token`, `google_id` | Pass |
| Consent recorded with a version | `POST /api/consent` stores `consented_at` and `consent_version`. `GET /api/user` returns `consent_required`, which is true until the user accepts the current `pdpa.consent_version` (now `2026-10`) | Pass (API) |
| Consent screen | Shown when `consent_required` is true; blocks the app until accepted | Frontend (KU-BCG, Tigger) |
| Right to erasure | `DELETE /api/profile`. Google accounts confirm with `confirm_email`; password accounts confirm with `password`. Search history and learning progress cascade on delete. Activity logs keep the event with `user_id = NULL`, so they are anonymised. The session is invalidated | Pass (API) |
| Delete account UI | Profile page, behind a confirmation dialog | Frontend (KU-BCG, Tigger) |

Tests: `tests/Feature/Api/PdpaApiTest.php` covers consent, `consent_required`, hidden `google_id`, and deletion of a Google account by email.
